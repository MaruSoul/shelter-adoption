# Домівка – вебсистема прилаштування тварин притулку

Каталог котів і собак, які шукають дім, анкета «Взяти додому» без реєстрації, кабінет волонтера з розміщенням знайдених тварин, панель адміністратора притулку з обробкою анкет, модерацією та блоговим конструктором статей.

## Можливості

**Для відвідувачів**
- каталог з фільтрами (вид, вік, стать, порода, забарвлення, область і населений пункт, стерилізація, вакцинація) та готовими добірками на головній;
- гра «Хто мій друг?» на головній – випадкове знайомство з твариною, яка шукає дім;
- сторінка тварини з галереєю (стрілки, клавіші ← →, свайп), кнопками «Поділитися» та закріпленою кнопкою «Взяти додому» на телефоні;
- «Обрані» – сердечко на картці: у гостя список живе в браузері, після входу переноситься в акаунт;
- анкета на прилаштування без реєстрації; якщо пошта збігається з підтвердженим акаунтом, анкета зʼявляється в кабінеті;
- блог із часом читання та блоком «Читайте також»;
- дві мови сайту з окремими адресами: українська (`/tvaryny`) і англійська (`/en/tvaryny`), теги hreflang; перемикач UA/EN веде на ту саму сторінку іншою мовою;
- окрема сторінка каталогу для кожного виду (`/tvaryny/cat`, `/tvaryny/dog`); фото тварини відкривається на весь екран.

**Для волонтерів (кабінет)**
- розміщення знайденої тварини з фото, редагування та видалення своїх карток;
- статус модерації й коментар модератора; профіль з телефоном і областю, які підставляються в анкети.

**Для адміністратора притулку**
- огляд із клікабельними лічильниками; модерація карток волонтерів з усіма фото й повним текстом;
- анкети: фільтри, усі анкети тієї ж людини, звʼязок одним дотиком (дзвінок, Viber, Telegram, лист), історія статусів;
- тварини, блоговий конструктор статей (текст, зображення, цитати, списки, картки тварин, відео з YouTube/Vimeo; у тексті – посилання `[текст](/адреса)` і **жирний**), налаштування притулку й посилання на соцмережі у футері;
- «Допомога»: способи фінансової допомоги вкладками (банка Monobank, реквізити з перевіркою IBAN, PayPal, інше посилання), порядок і приховування, посилання на звіти; на сайті – сторінка `/help` і блок на головній;
- довідники: види тварин, породи, забарвлення, рубрики блогу (назви UA | EN; запис, що використовується, не видаляється);
- SEO: Title, Description, H1 і SEO-текст для головної, каталогу, кожного виду й блогу; Title/Description статей; Google Search Console й Analytics (лише зі згодою відвідувача);
- усі тексти, які бачать відвідувачі (кличка, історія, поведінка, умови прилаштування, заголовок, анонс і блоки статті,
  назва, підзаголовок і адреса притулку), вводяться парою «UA | EN»; лічильник показує, скільки ще не перекладено,
  а списки тварин і статей – позначку й фільтр «без перекладу». Без перекладу сайт показує український текст із позначкою.

**Технічне**
- SEO: мета-теги Open Graph, sitemap.xml з обома мовами, розмітка schema.org (AnimalShelter, BlogPosting, BreadcrumbList), `/llms.txt` для ШІ-асистентів;
- доступність: семантична розмітка, видимий фокус, підписи для екранних читачів, повага до «зменшити рух»;
- nginx стискає текстові відповіді (gzip) і довго кешує файли збірки.

## Стек

| Рівень | Технології |
|---|---|
| Сервер | PHP 8.5, Laravel 13, Livewire 4, Laravel Fortify (автентифікація) |
| Інтерфейс | Blade, Livewire, Alpine.js, Tailwind CSS 4, шрифти Nunito та Inter (локально) |
| Дані | PostgreSQL 17 |
| Інфраструктура | Docker Compose: nginx, php-fpm, черга, PostgreSQL, Mailpit |
| Тести | Pest 4 (модульні та функціональні тести на PostgreSQL) |

Точні версії залежностей зафіксовано в `composer.lock` і `package-lock.json`.

## Запуск через Docker (рекомендовано)

Потрібні лише [Docker Desktop](https://www.docker.com/products/docker-desktop/) і Git.

```bash
git clone https://github.com/MaruSoul/shelter-adoption.git
cd shelter-adoption

# 1. Налаштування середовища і ключ шифрування застосунку
cp .env.example .env
sed -i.bak "s|^APP_KEY=.*|APP_KEY=base64:$(openssl rand -base64 32)|" .env && rm .env.bak

# 2. Збирання образів і запуск (перший раз – кілька хвилин)
docker compose up -d --build

# 3. Схема бази й демонстраційні дані
docker compose exec app php artisan migrate --seed --force
```

Після запуску:

| Адреса | Що там |
|---|---|
| http://localhost:8080 | сайт |
| http://localhost:8080/admin | панель адміністратора притулку |
| http://localhost:8025 | Mailpit – усі листи, які надсилає сайт |

Міграції бази даних виконуються автоматично під час старту контейнера `app`.

### Демонстраційні акаунти

| Роль | E-mail | Пароль |
|---|---|---|
| Адміністратор притулку | admin@domivka.local | admin-password |
| Волонтер (має розміщені тварини та анкету) | volunteer@domivka.local | user-password |
| Інший користувач (для перевірки прав доступу) | andrii@domivka.local | user-password |

> Дані вигадані. Демонстраційний набір – 40 тварин (20 котів і 20 собак), у кожної кілька фото з Unsplash
> (`database/seeders/photos/pets`, автори – у `database/seeders/photos/CREDITS.md`). Опис, порода, окрас і місто
> беруться з `info.json` у папці кожної тварини (`database/seeders/Support/DemoPets.php`).

### Корисні команди

```bash
docker compose logs -f app                       # журнал застосунку
docker compose exec app php artisan migrate:fresh --seed --force   # перестворити базу з демо-даними
docker compose exec app php artisan db:seed --class=DemoTranslationsSeeder --force   # додати англійську до наявних демо-даних
docker compose down                              # зупинити
docker compose down -v                           # зупинити й видалити дані (база, фото)
```

## Автоматичні тести

Тести працюють з окремою базою `shelter_test` (створюється автоматично під час першого запуску PostgreSQL) і ніколи не чіпають основну базу.

```bash
docker compose --profile tests run --rm tests
```

Що покривають тести:

- каталог: видимість за статусами, фільтри за видом і віковими групами, порожня вибірка, пагінація;
- анкета: успішне подання гостем, перевірка полів, нормалізація телефону, захист від дублікатів, поле-пастка для ботів, обмеження частоти, прилаштована тварина;
- бізнес-процес: матриця переходів статусів (усі 36 пар), прилаштування із закриттям інших анкет, гонка двох прилаштувань на рівні СУБД;
- права доступу: панель лише для адміністратора, кабінет лише з підтвердженою поштою, чужі анкети й картки, роль через реєстрацію;
- модерація карток волонтера, видалення картки волонтером, завантаження фото, блоковий конструктор, екранування HTML (XSS), sitemap;
- обрані (гість і користувач, синхронізація), профіль і підстановка контактів, привʼязка анкети до акаунта за поштою, гра «Хто мій друг?», кеш налаштувань притулку.

## Локальний запуск без Docker

Потрібні PHP 8.5+ з розширеннями `pdo_pgsql`, `gd`, `intl`, `zip`, `exif`, Composer, Node.js 26 і PostgreSQL.

```bash
composer install
npm ci && npm run build
cp .env.example .env            # змінити DB_HOST=127.0.0.1, MAIL_MAILER=log
php artisan key:generate
php artisan migrate --seed
php artisan storage:link
php artisan serve               # http://127.0.0.1:8000
php artisan queue:work          # в окремому терміналі – мініатюри фото й листи
./vendor/bin/pest               # тести (потрібна база shelter_test)
```

## Структура проєкту

```
app/
  Enums/          статуси й довідники-переліки (матриця переходів анкети – ApplicationStatus)
  Livewire/       сторінки з інтерактивністю: каталог, анкета, кабінет, панель адміністратора
  Services/       бізнес-логіка: подання анкети, зміна статусів і прилаштування, фото, блоки статей
  Support/        допоміжне: нормалізація телефону, розмітка schema.org
  Policies/       правила доступу до тварин і анкет
  Models/         моделі Eloquent
database/
  migrations/     схема БД (зокрема часткові унікальні індекси)
  seeders/        демонстраційні дані, фото тварин і статей, населені пункти України (КАТОТТГ)
resources/views/  шаблони Blade (маскот Лапа – components/mascot)
docker/           Dockerfile, nginx, PostgreSQL
tests/            автотести Pest
```

## Розгортання на сервері

Робоча копія: **https://pet.tinycdn.cloud**. На сервері встановлені Docker і nginx; HTTPS забезпечує nginx
із сертифікатом Let's Encrypt (certbot) і передає запити контейнеру `web` на `127.0.0.1:8080`.
Копія конфігурації nginx – `docker/host-nginx/pet.tinycdn.cloud.conf`. Git на сервері не використовується.

**Налаштування.** У робочій папці на ноутбуці лежать два файли (обидва не потрапляють у git і в образ Docker):

| Файл | Для чого |
|---|---|
| `.env` | локальний запуск (`APP_ENV=local`, http://localhost:8080) |
| `.env_prod` | точна копія `.env` на сервері; шаблон – `.env.production.example` |

**Оновлення сайту:**

1. Завантажити всю папку проєкту на сервер.
2. На сервері видалити `.env` і перейменувати `.env_prod` на `.env`.
3. Зібрати й перезапустити контейнери (код вбудовується в образ, тому без `--build` зміни не зʼявляться):

```bash
docker compose up -d --build
```

Міграції виконуються автоматично під час старту контейнера. Якщо змінюєте `.env` прямо на сервері, ту саму зміну
внесіть у `.env_prod` на ноутбуці, інакше наступне завантаження її перезапише. Демо-акаунти з таблиці вище варто
змінити або видалити: паролі опубліковані в цьому README.

**Пошта.** Листи потрапляють у Mailpit, який слухає лише `127.0.0.1` (в листах персональні дані з анкет).
Подивитися з ноутбука: `ssh -L 8025:localhost:8025 користувач@сервер`, далі http://localhost:8025. Щоб листи
доходили до людей, вкажіть у `.env` реквізити SMTP-сервісу (`MAIL_HOST`, `MAIL_PORT`, `MAIL_USERNAME`, `MAIL_PASSWORD`)
і перезапустіть.

**Резервна копія бази:**

```bash
docker compose exec -T db pg_dump -U shelter shelter | gzip > backup-$(date +%F).sql.gz
```
